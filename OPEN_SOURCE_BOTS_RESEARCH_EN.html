🔎 Open-Source Trading Bots

Research report: what GitHub's trading bots teach us before we design our own

35 projects💱 Forex · 🥇 Metals · 🪙 CryptoResearch only — nothing was run or traded
📌Important

Research and learning only.

  • We did not install, run or test any of these bots, and no trades were placed.
  • Nothing here is financial advice or a suggestion to trade.
  • Profits that projects claim are their claims, not verified facts.
  • All facts were collected on 30 September 2026; platforms change often, so re-check before relying on them.

This report is the companion of the 📘 Trading Learning Guide (docs/guide/TRADING_GUIDE_EN.md). When a term is already explained there, you'll see a pointer like (Guide Part 11).

⚡ The main findings at a glance

  1. No project covers all three of our platforms (MT5 + Binance + MEXC).

    • The crypto frameworks don't do MT5.
    • The MT5 bots don't do crypto.
    • The one tutorial that tried both (Part 5.1) never finished its crypto side.

    → We'll build our own small framework, re-using proven ideas and a few libraries (ccxt for crypto, mt5linux for MT5 on Linux).

  2. The best projects separate a pure "brain" from platform "connectors" and run the same strategy code in backtest, paper and live: freqtrade, Jesse, NautilusTrader, aiomql, OctoBot, chrisleekr (Parts 2, 3, 5, 8). That's exactly our design.

  3. Hard-coded symbol facts were the most common bug we found. One bot would risk 5× too much on silver; another's gold stops were 10× too small at a different broker. This confirms our rule: read everything from the platform (0.8, 8.6).

  4. Many impressive results don't survive honest testing. They are in-sample, powered by a hidden martingale grid, or pure marketing. The most honest gold study we found (Part 7.5.1) reports "No strategy has a statistically demonstrated edge": opening-range breakout, RSI2 and Bollinger reversion all lost money after costs.

  5. Safety engineering matters more than clever strategies. The protections that matter:

    • broker-side stops
    • "fail-closed" demo checks
    • kill switches
    • risk gates outside the strategy

    One popular grid bot's "paper mode" on MEXC silently trades real money (Part 3.3).

  6. Safe testing is possible on every market (Parts 8 and 12):

    • MT5 demo for forex and metals.
    • Binance Spot Testnet (it even lists PAXGUSDT) for connector plumbing; Demo Trading for realistic paper results.
    • MEXC has no testnet, so we build our own paper engine on its live public prices.

  7. Metals need special care (Part 7):

    • gold moves ~4–5× more than EURUSD
    • silver's lots are 50× bigger in ounces and it's ~8–9× costlier to trade relative to price
    • gold closes daily at the rollover
    • MT5's Python API can't tell us the trading hours

  8. AI "trading agents" are good assistants, not traders. We found no evidence of reliable live profits from LLM agents (Part 6).

0.1 GitHub words

🧒Like I'm 10

GitHub is a giant public library of computer programs. Each program lives on its own shelf (a repository). Anyone can read the books, copy recipes, and leave a ⭐ if they liked it. But a book with many stars is popular, not necessarily correct.

Word Simple meaning
Open-source The program's code is public: anyone can read it, learn from it, and (depending on the licence) reuse it.
Repository (repo) One project's folder on GitHub, with all its files and history. Written as owner/name, e.g. freqtrade/freqtrade.
Stars ★ Like "likes". They measure popularity, not whether the bot makes money.
Fork A copy of someone's repo that another person continues separately.
Last push / maintained When the code was last changed. A trading bot that hasn't been updated for years may break, because exchanges change their APIs.
Archived The owner has officially stopped the project. Read-only.
README The front page of a repo that explains what it is.
Issue / Pull request A reported problem / a proposed code change. Lots of recent activity = a living project.

Licences say what you may do with someone's code:

Licence What it means for us (simplified, not legal advice)
MIT, Apache-2.0, BSD "Permissive": you may reuse the code, even in a private or commercial project, if you keep the copyright notice.
GPL-3.0 "Copyleft": if you copy GPL code into your program and give that program to others, your program must also be GPL (open-source).
AGPL-3.0 Like GPL, but it also applies when people use your program over a network (e.g. a web app).
LGPL A softer GPL, mostly for libraries you use rather than copy.
NOASSERTION / custom / none Unusual or missing licence. If there's no licence, you legally may not reuse the code at all. Read before using.
ℹ️Note

We are learning ideas, not copying code. Ideas and strategies (e.g. "buy when the fast average crosses above the slow one") aren't owned by anyone; the code that implements them is. That's one more reason to design our own bot.

0.2 What kind of project is it?

🧒Like I'm 10

Think of a kitchen. A library is a set of knives. A framework is a whole kitchen with an oven and a fridge, where you bring your own recipe. A strategy is the recipe. A ready-made bot is a robot chef that already knows one recipe. An Expert Advisor is a robot chef that only works inside one particular kitchen (MT5).

Type What it is Example you'll meet
Library A toolbox other programs use. It doesn't trade by itself. ccxt (talks to 100+ crypto exchanges), the MetaTrader5 Python package
Framework / engine A complete bot "engine": data, orders, backtesting, risk tools. You plug in the strategy. freqtrade, Jesse, Hummingbot, OctoBot, aiomql
Strategy Only the rules (one file of code) that run inside a framework. NostalgiaForInfinity (runs inside freqtrade)
Ready-made bot A bot with one built-in way of trading, configured with settings. binance-trading-bot, grid bots
Expert Advisor (EA) A bot that runs inside MetaTrader and is written in MQL5 (MetaTrader's C++-like language). geraked/metatrader5, EA31337, GOLD_ORB
Tool / utility A helper, not a strategy (e.g. calculates position size, or closes everything in an emergency). PositionSizer, Account-Protector
Backtesting library Software that tests rules on past prices. backtesting.py, vectorbt, backtrader, Lean
AI / LLM agent Programs where an AI model (a machine-learning model, or an LLM, a Large Language Model like ChatGPT or Claude) helps make or explain decisions. TradingAgents, FinRL, FreqAI

0.3 Testing words

These words decide whether a bot's results can be trusted. They extend Guide Parts 14 and 20.

Word Simple meaning
Backtest Running the bot's rules on past prices to see what would have happened.
Dry-run / paper trading Running the bot on live prices but with pretend orders (no money).
Demo account A broker account with virtual money (your Exness MT5 demo). The orders are real orders on a fake balance.
Live trading Real money. Not part of this project.
Optimisation / hyperopt Letting the computer try thousands of parameter combinations (e.g. RSI 10, 12, 14…) and keep the ones that did best on past data. ("Hyperopt" = hyper-parameter optimisation, freqtrade's name for it.)
Overfitting Tuning rules so perfectly to the past that they fail in the future. Like a student who memorised last year's exam answers and fails this year's exam.
In-sample / out-of-sample In-sample = the data you tuned on. Out-of-sample = fresh data the strategy has never seen. Only out-of-sample results mean much.
Walk-forward testing Repeating "tune on one period → test on the next period" many times, moving forward through history. A strong defence against overfitting.
Look-ahead bias A backtest bug where the rules accidentally use information from the future (e.g. today's closing price to decide a trade at today's open). It makes results look amazing and fake.
Slippage / spread / commission modelling Whether a backtest charges realistic costs. Without them, results are too optimistic. (Guide Part 9)

Numbers used to judge a strategy (you'll see these in reports):

Metric Meaning Rough reading
Net profit / return % How much the account grew. Meaningless alone: always read it with drawdown.
Number of trades How many trades the test contains. Under ~100 trades says very little.
Win rate % of trades that made money. High win rate can still lose money if losses are big.
Profit factor Total money won ÷ total money lost. Below 1 = losing; 1.2–1.5 is decent; above 3 in a backtest is suspicious (overfitting?).
Max drawdown The biggest fall from a peak. (Guide Part 13) The "pain" number. Can you survive it?
Expectancy Average result per trade. (Guide Part 13) Must be positive after costs.
Sharpe ratio Return divided by how bumpy the ride was. ~1 is decent, ~2 is very good, above 3 in a backtest is suspicious.

0.4 Strategy-style words

Guide Part 12 explains trend following, range trading, breakout, mean reversion, DCA and grid. Bots add a few more:

Style Simple meaning Main danger
Trend following Trade in the direction the price is already going. Many small losses when the market goes sideways.
Mean reversion Bet that a price that moved "too far" comes back to its average. A strong trend keeps going "too far".
Breakout Enter when price escapes a range. False breakouts (fakeouts).
Grid Put a ladder of buy orders below and sell orders above the price; profit from zig-zags. A strong one-way move leaves you holding a big losing position.
DCA with "safety orders" In bots, DCA often means buying more each time the price falls to lower your average price. If the price keeps falling, the position keeps growing: big losses.
Martingale Doubling the size after every loss. Can blow up an account quickly. A red flag in any bot.
Market making Constantly offering to buy slightly below and sell slightly above the price to earn the spread. Fast moves; being left holding the wrong side ("inventory risk").
Arbitrage Buying on one exchange and selling on another where the price is higher. Fees, transfer delays, and competition from professional bots.
Scalping Many tiny trades held for seconds or minutes. Costs (spread and fees) eat everything.

0.5 Risk-control words

Word Simple meaning
Stop-loss / take-profit / trailing stop (Guide Part 8): automatic exits for a loss, a profit, or a stop that follows the price.
Breakeven stop Moving the stop-loss to the entry price once the trade is in profit, so the trade can no longer lose (except for slippage).
ATR-based stop Placing the stop a multiple of the ATR (the average candle size, Guide Part 11) away from the entry, so the stop adapts to how "wild" the market is.
ROI table freqtrade's time-based take-profit: e.g. "exit at +4% profit at any time, or at +1% after 60 minutes, or at 0% after 3 hours".
Position sizing How big each trade is: a fixed lot, or calculated from % risk of the account and the stop distance (Guide Part 13).
Max open trades / exposure limit A cap on how many trades, or how much money, can be in the market at once.
Cooldown Pausing a symbol or the whole bot for a while after losses.
Kill switch / circuit breaker An automatic "stop everything" when something goes wrong (e.g. the account drops 5% in a day).

0.6 Market labels: 💱 Forex, 🥇 Metals, 🪙 Crypto, or 🔁 Both

Our bot must work on forex, metals and crypto, so every project, strategy and idea in this report gets a label:

Label Meaning
💱 Forex Works well for currency pairs on MT5 (e.g. EURUSD), but not (or poorly) for crypto.
🥇 Metals Specific to gold (XAUUSD) and silver (XAGUSD) on MT5, or to gold-backed tokens such as PAXG on Binance/MEXC.
🪙 Crypto Works well on crypto exchanges like Binance and MEXC, but not (or poorly) for MT5 CFDs.
🔁 Both The idea transfers across markets, sometimes with small adjustments.

Gold-backed token. A crypto token that represents real gold stored in a vault. For example, PAXG (Paxos Gold) is designed so that 1 token = 1 troy ounce of gold. It trades like any coin on a crypto exchange: 24/7, in coin units, with maker/taker fees.

0.7 Architecture words for a multi-market bot

🧒Like I'm 10

Think of a games console and its controllers. The console (the brain) runs the game (the strategy). Different controllers (the connectors) plug into it: one for MT5, one for Binance, one for MEXC. A new controller doesn't need a new game.

Word Simple meaning
Brain / core The part of the bot that is the same for every market: strategy, risk management, backtesting, journal.
Connector / adapter The part that talks to one platform: it fetches its prices, sends its orders, reads its balance, and translates everything into the brain's common language.
Unified API A library that gives many exchanges the same commands (e.g. ccxt: fetch_ohlcv() works on Binance and MEXC alike).
Normalisation Converting each platform's formats into one common format: symbols (EURUSDm vs BTC/USDT), sizes (lots vs coins), time (MT5 server time vs UTC).
Testnet A crypto exchange's separate practice copy for developers, with fake coins but the real API (Binance has one).
Paper trading (simulated fills) Our own program pretends orders were filled using real live prices, without sending anything to the exchange. Useful where no testnet exists.
Demo account A real broker account with virtual money (your Exness MT5 demo).

0.8 Symbol specifications: facts the bot must read, never assume

🧒Like I'm 10

Every game has its own rulebook. In football the ball is round; in rugby it's oval. If you play rugby with football rules, you'll get it wrong. Each symbol (EURUSD, XAUUSD, XAGUSD, BTCUSDT, PAXGUSDT) has its own rulebook, called its specification, and each platform can write that rulebook slightly differently. So the bot must read the rulebook every time instead of remembering one.

A symbol specification is the list of facts about one tradable thing on one platform. Our rule is: the bot never types these facts into its code. It asks the platform for them.

Fact Simple meaning Example of why it can't be assumed
Symbol name The exact name the platform uses Gold might be XAUUSD at one broker and XAUUSDm on another account type (the suffix differs); Binance writes BTCUSDT, ccxt writes BTC/USDT
Contract size How much of the asset 1 lot represents Gold: commonly 100 oz per lot; silver: commonly 5,000 oz per lot. Using gold's number for silver would make the position 50× too big
Digits / point How many decimals the price has; a point is the smallest price step shown A "400 points" stop is $4 of gold price at one broker and $0.40 at another (a real bug we found, Part 4)
Tick size / tick value The smallest possible price move, and how much money that move is worth for 1 lot This is the key number to turn "risk $10" into a lot size
Volume min / max / step Smallest order, biggest order, and the size increments allowed 0.01 lots on MT5; 0.00001 BTC on Binance
Minimum notional Crypto exchanges' smallest order value (e.g. at least 5 USDT) A tiny order is rejected
Stops level (minimum stop distance) How close to the current price a stop-loss or take-profit may be placed A stop set too close is rejected by MT5
Trading sessions / hours When the symbol can be traded Metals often have a daily break; crypto never closes
Swap / funding / fees The costs of holding and trading (Guide Part 9) Different for every symbol, direction (buy/sell) and account type

Some things change every second, so the bot must measure them live:

  • Current spread = ask − bid, right now. It widens at night, at the daily rollover and during news (Guide Part 9).
  • Current volatility, e.g. with ATR (Guide Part 11). Gold might move $10 in a calm hour and $40 during a US news release.

Things that are our own choices go in a settings file: a simple text file (for example in YAML or TOML format) that we can edit without touching the code. Examples: which symbols to trade, the % risk per trade, the maximum trades per day, the daily loss limit.

flowchart LR
    P["🏛️ Platform<br/>(MT5 / Binance / MEXC)"] -- "symbol specs:<br/>contract size, tick value,<br/>volume step, sessions, fees" --> BR["🧠 Brain"]
    P -- "live prices:<br/>bid/ask → spread,<br/>candles → ATR" --> BR
    S["📝 Settings file<br/>(our choices: symbols,<br/>risk %, limits)"] --> BR
    BR --> D["Decision:<br/>trade or not,<br/>size, stop, target"]

2Crypto bot frameworks 🪙

These are the two most important frameworks (bot engines where you plug in your own strategy) in the crypto world, plus a very famous strategy that runs on one of them. None of them connects to MT5, but their design ideas are the best examples we found for our own "brain".

2.1 freqtrade: the most popular open-source crypto bot
Repo freqtrade/freqtrade
Popularity / activity ≈55,000 ★, updated daily (version 2026.9)
Licence / language GPL-3.0 (see 0.1) / Python
Type Framework + ready-to-run bot engine
Market label 🪙 Crypto for the engine · 🔁 Both for most of its ideas
🧒Like I'm 10

freqtrade is like a driving school car with dual controls. You write the driving rules (the strategy). freqtrade drives the car, checks the mirrors (risk protections), can drive on a simulator first (backtest), then on an empty practice road (dry-run), and has an instructor's brake pedal (protections and Telegram commands).

What it does. Everything a crypto bot needs except the strategy: it downloads prices, calculates indicators, sends orders to exchanges, tracks open trades in a database, backtests, optimises, shows a web dashboard (FreqUI) and can be controlled from Telegram (/status, /profit, /forceexit…).

How a strategy works in freqtrade. A strategy is one Python file with three steps:

flowchart LR
    A["1️⃣ populate_indicators<br/>add indicator columns<br/>(RSI, EMA, Bollinger...)"] --> B["2️⃣ populate_entry_trend<br/>mark candles where we<br/>want to ENTER (1 = yes)"]
    B --> C["3️⃣ populate_exit_trend<br/>mark candles where we<br/>want to EXIT"]
    C --> D["⚙️ freqtrade engine<br/>turns marks into orders,<br/>applies stops and ROI"]

The strategy never talks to the exchange. It only marks rows in a table of candles. The engine does the rest. This separation is exactly what we want for our "brain".

The bundled example strategy (SampleStrategy). We read its code. It runs on 5-minute candles.

New indicators here:

  • TEMA (Triple Exponential Moving Average) is a moving average that reacts faster than a normal EMA.
  • Bollinger middle band is simply the 20-candle average price (Guide Part 11).
Rule (all must be true) In plain words
Enter long RSI crosses up through 30 · TEMA is at or below the Bollinger middle band · TEMA is rising "Price was oversold, is still on the cheap side of its average, and has started turning up."
Exit RSI crosses up through 70 · TEMA above the middle band · TEMA falling "Price became overbought, is on the expensive side, and has started turning down."
Take-profit (ROI table) +4% at any time; +2% after 30 min; +1% after 60 min The longer the trade lasts, the smaller the profit it accepts.
Stop-loss −10% Exit if the trade loses 10%.
  • Market label: 🔁 Both (logic only). The rules use only prices, so they work on any market. But the numbers are made for crypto's big moves: EURUSD might need days or weeks to move 4%, and on 5-minute candles the forex spread would eat a large part of each target. On forex the stop and target would have to be re-scaled (e.g. with ATR or pips).

How it manages risk (the most useful part for us):

  • Stop-loss types: fixed %, trailing, trailing that starts only after some profit, or fully custom (e.g. ATR-based). A stop can only move in the favourable direction.
  • Stop on the exchange: the stop can be placed on the exchange's server, so it still works if our bot crashes. If placing it fails, freqtrade sells at market immediately ("emergency exit").
  • Position size: a fixed amount per trade, or the balance split equally between the allowed open trades. There is no built-in "% risk" sizing (you must code it yourself with a callback).
  • Max open trades: a required setting; only one trade per coin at a time.
  • Protections (automatic kill switches):
Protection What it does (documented example)
StoplossGuard If 4 stop-losses happen within 24 candles, pause trading for 4 candles.
MaxDrawdown If the account falls 20% within a period, pause trading.
LowProfitPairs Pause a coin that has been losing (e.g. less than 2% profit over its last trades).
CooldownPeriod Wait 2 candles after closing a trade before re-entering the same coin.
  • Leverage (futures): optional, with a safety buffer before the liquidation price. The docs warn: "a stoploss of 10% on a 10x trade would trigger on a 1% price move."

Testing tools.

  • Backtesting with a written list of assumptions. For example, when a candle touched both the stop-loss and the take-profit, freqtrade pessimistically assumes the low came first, so the stop was hit. A tool (lookahead-analysis) also detects look-ahead bias (see 0.3).
  • Dry-run: trades on live prices with a simulated wallet, with no API keys needed. freqtrade has no Binance testnet support; its official answer is "use dry-run".
  • Hyperopt (see 0.3) tries thousands of settings. It's powerful, and it makes overfitting very easy.
  • FreqAI: an optional machine-learning module (see Part 6).

Platforms. Officially supported: Binance (spot and futures), Bybit, OKX, Kraken, Gate, Bitget, HTX, BingX, Hyperliquid. MEXC is not officially supported: freqtrade would start with a warning that it "may work flawlessly… or have serious issues". No MT5, no forex.

✅ Strengths ⚠️ Weaknesses / limitations
Very mature, huge community, excellent documentation Crypto only (no MT5) and MEXC not supported
Strategy is separated from execution → same code for backtest and live No built-in % risk sizing; stops and targets are in %, not prices
Honest, documented backtest assumptions + look-ahead checker Configuration is complex; settings in the config override the strategy
Protections (kill switches), server-side stops, Telegram control Hyperopt invites overfitting
GPL-3.0: copying its code would force our bot to be GPL

What could inspire our bot:

  • 🔁 Strategy = signal columns on a candle table, with the engine doing orders. The same strategy code runs in backtest and live.
  • 🔁 A Protections module: StoplossGuard, MaxDrawdown, Cooldown, LowProfit. These are a must-have for us.
  • 🔁 A server-side stop plus an "emergency exit" fallback. On MT5 this means attaching SL/TP to the position itself.
  • 🔁 A written list of backtest assumptions and a look-ahead-bias test.
  • 🔁 Separate databases for paper and live trades, and API secrets kept in a separate file.
  • 🪙 A capability list per exchange (does it support stops on the exchange? what order types?). This is a great pattern for our connectors (see Part 8).

2.3 NostalgiaForInfinity (NFI): a famous but gigantic strategy

Imagine a cookbook where one recipe is 58,000 lines long and says things like "add salt, except on Tuesdays in 2022, because that one time the cake burned". It might taste good on the days it was written for, but nobody can really understand it or predict how the next cake will turn out.

What it does. It trades 40–80 crypto coins at once on 5-minute candles, using many timeframes (5 min up to 1 day) and Bitcoin's trend as extra information.

How its strategy works.

  • The current file has 58,171 lines. The part that decides entries alone is about 23,700 lines.
  • There are about 84 different entry conditions, grouped into "modes" (normal, pump, quick, rebuy, rapid, grind, scalp…).
  • Each entry gets a tag (a label naming the mode), and the tag decides which exit rules apply to that trade.
  • Example: entry condition #1 alone is about 486 lines of filters (RSI, Aroon, StochRSI, MFI, Williams %R… on 5 timeframes). Its core idea is "EMA26 is well above EMA12 (a sharp drop) and price is below the lower Bollinger Band", i.e. buy a sharp dip.

Exits and risk management: the worrying part.

  • The normal stop-loss is set to −99%, which means effectively no stop-loss.
  • Instead it uses DCA / "grinding" (see 0.4): it buys more as the price falls (e.g. extra buys at −6%, −7%, −8%, −9%, −10%). It also partly sells at some loss levels ("de-risking").

  • In futures mode it uses 3x leverage.

  • "(4 losses, all in 2022)"
  • "DOGE 2024-04-05… recovered"
  • "Black Thursday (ADA 2020-03-13)"
  • "INJ 58 adds, 28x"

That last one describes one trade where the bot bought 58 more times as the price fell.

An auto-updater can also replace the strategy code while the bot is running, so the rules can change without anyone reviewing them.

2.4 Jesse: a clean, research-focused framework
Repo jesse-ai/jesse
Popularity / activity ≈8,600 ★, updated September 2026 (version 3.2)
Licence MIT for the core (permissive). Live/paper trading is a closed, paid plugin
Type Framework focused on research and backtesting
Market label 🪙 Crypto for live trading · 🔁 Both for backtesting (it can import forex data)
🧒Like I'm 10

If freqtrade is a car that drives itself from a table of instructions, Jesse is a car where you answer simple questions at every stop: "Should I go now?" "Where exactly do I stop if things go wrong?" "Where do I take profit?" It's very easy to read.

How a strategy works. You answer a few questions (methods) on every new candle:

Method Question it answers
should_long() / should_short() "Should I open a trade now?" (only asked when no trade is open)
go_long() / go_short() "How much, at what price, with which stop-loss price and take-profit price?"
should_cancel_entry() "My entry order hasn't filled yet. Should I cancel it?"
update_position() "I'm in a trade. Should I move the stop, add more, or close now?"
filters() Extra named checks that must pass (e.g. "is the reward at least 2× the risk?")
trading_hours() "Which hours am I allowed to trade?" The docs even show a forex week schedule

Stops and targets are written as prices, not %. Jesse then picks the order type by itself. For example, when going long:

  • entry = current price → a market order
  • entry below the current price → a limit order
  • entry above the current price → a stop order

Example strategies we read (their README says they are "NOT… ready-to-go profitable strategies… Be aware of overfitting!"):

Strategy Entry Exit Label and why
SMA Crossover Long when SMA50 > SMA200, short when below Close on the opposite cross 🔁 Both. Trades last weeks, so swap (forex) or funding (crypto futures) costs add up

Donchian breakout Long when the close breaks above the highest high of the previous 20 candles (a Donchian channel), only above SMA200 Exit below the lowest low of 20 candles 🔁 Both. On forex, weekend gaps can jump past the breakout level

A lesson in reading results. The SMA Crossover example reports +84.7% on Bitcoin (3-hour candles, June 2019 → June 2020). But that's only 13 trades on one coin in one year, with a maximum drawdown of −53.7%. It also uses 100% of the balance per trade with no stop-loss. A big return with a −54% drawdown and 13 trades proves almost nothing (see 0.3).

Risk management tools.

  • risk_to_qty, a position-size calculator. It is the formula from Guide Part 13: quantity = (capital × risk %) ÷ |entry price − stop price|. We read its code and found two small quirks: the fee is subtracted twice, and the documented default precision (3) differs from the code (8). This shows why we will write and test our own.
  • Also: limit_stop_loss (caps how far away a stop can be), estimate_risk, and kelly_criterion (a formula for bet size; too aggressive for beginners).
  • No automatic kill switches like freqtrade's Protections.

Testing tools.

  • Candle-by-candle backtesting, and optimisation of settings.
  • Monte Carlo: shuffling the order of past trades thousands of times to see the range of possible drawdowns, not just the one that happened.
  • Rule significance testing: checking whether a rule beats random entries.
  • But the simulator uses one simple fee %. It has no spread and no swap, which matters for forex.

Platforms. Backtesting: Binance, Bybit, Coinbase, KuCoin, Gate, Kraken, Bitfinex, plus imported forex, stock and index data. Live and paper: many crypto exchanges, only with the paid plugin (the free plan allows testnets only). No MEXC, no MT5.

  • 🔁 The question-based lifecycle (should_enter → go → update_position → exit) with prices for stops and targets. The same strategy then works in pips (forex) or USDT (crypto).

2.5 How these frameworks keep the strategy separate from the exchange

This is the most important finding for our shared brain + connectors design:

flowchart LR
    subgraph FT["freqtrade"]
        S1["Strategy<br/>(signal columns only)"] --> E1["Bot engine<br/>(loop, wallet, protections)"] --> X1["Exchange class<br/>(wraps ccxt)"]
        X1 --> B1["Binance subclass<br/>+ capability list"]
        X1 --> B2["Bybit subclass<br/>+ capability list"]
    end
    subgraph JS["Jesse"]
        S2["Strategy<br/>(intent: qty + prices)"] --> BR["Broker<br/>(buy_at, sell_at...)"] --> API["API<br/>(one driver per exchange)"]
        API --> SB["Sandbox driver<br/>(backtest / paper)"]

  • In freqtrade, the strategy never calls the exchange. Each exchange is a small subclass that declares a capability list, e.g. "supports stop-loss on the exchange: yes/no", "max candles per request: 1000", "supports demo trading: yes/no".
  • In Jesse, the strategy only expresses an intent (buy this quantity at this price, stop here). A driver with just six methods turns the intent into orders. The same interface is used by a Sandbox (simulated) driver for backtesting and paper trading.
  • NFI is the counter-example: it puts exchange-specific details inside the strategy. That's exactly what we want to avoid.

3Other crypto bot styles: market making, grid, DCA and trailing 🪙

These four projects trade in ways that are quite different from "indicator says buy". None of them supports MT5, forex or metal CFDs; all four are crypto-only. But their engineering (safety, testing, connectors) is some of the best we found.

New words used in this part:

Word Simple meaning
CEX / DEX Centralised exchange (Binance, MEXC: a company runs the order book) vs Decentralised exchange (runs on a blockchain, no company in the middle).
Inventory The coins a market maker is currently holding because its buy orders were filled.
Adverse selection Your waiting orders get filled exactly when you don't want them: in a fast drop, all your buys fill, then the price keeps falling.
Triple barrier Every trade gets three exits: a stop-loss, a take-profit, and a time limit. Whichever is hit first closes the trade.
Idempotent An action that is safe to repeat: sending the same order twice (e.g. after a network error) doesn't create two orders, because each order carries a unique ID.
Circuit breaker After several errors in a row, the bot stops calling the exchange for a while, then carefully tries again.

3.1 Hummingbot: the market-making specialist
Repo hummingbot/hummingbot
Popularity / activity ≈20,300 ★; very active (v2.17)
Licence Apache-2.0 (permissive)
Type Framework + ready-made strategy templates, mainly market making and arbitrage
Market label 🪙 Crypto only (market making needs a real order book)
🧒Like I'm 10

A market maker is like a currency exchange booth at an airport. It always offers to buy euros a bit cheaper and sell them a bit dearer than the real price. It earns the small difference (the spread) many times a day. The danger: if the euro suddenly crashes, the booth is stuck holding lots of euros it bought "cheap" that are now worth even less.

What it does. It keeps a buy order just below and a sell order just above the current price, and refreshes them every few seconds or minutes. When both fill, it has earned the spread.

How its strategies work.

  • Pure Market Making (classic): you set bid_spread and ask_spread (e.g. 1% below and above the mid price), the order size, and how often orders refresh.
    • Inventory skew: if it holds too many coins, it makes its buy orders smaller and its sell orders bigger, to drift back to a target (e.g. 50% coins / 50% cash).
  • Newer "controllers" add a triple barrier to every position. The defaults include stop 3%, target 2%, time limit 45 min, and 20× leverage on futures, which is dangerous to copy as a beginner. One version sets its spreads in units of volatility (NATR, a normalised ATR), so it quotes wider when the market is wild.
  • Avellaneda-Stoikov: a famous academic market-making model. It measures volatility and order-arrival speed live and adjusts prices to the inventory.
  • Arbitrage: market-make on one exchange and instantly hedge fills on another (cross-exchange), or trade price differences with a decentralised exchange (AMM arbitrage).

How it manages risk.

  • Inventory skew, price ceiling/floor, a triple barrier per position, a cooldown after a stop-loss, and a global kill switch (e.g. stop at −5%).
  • The classic strategy has no stop-loss.

Platforms.

  • Binance: spot, plus a futures testnet; no spot testnet found.
  • MEXC: spot only; its candle feed is "not built".
  • About 40 other venues.
  • Paper trading uses the real live order book with fills simulated locally (binance_paper_trade, mexc_paper_trade), and needs no API keys.

Hard-coding check.

  • ✅ Tick size, step size and minimum order value are read from the exchange.
  • ❌ Fees are hard-coded (Binance 0.1%, MEXC 0.05%), and the function that should fetch real fees is empty. You can override them in a file.
✅ Strengths ⚠️ Weaknesses / limitations
The most mature open-source market-making code Market making loses in fast moves (adverse selection)
Clean split: controller (decides) → executor (manages orders) → connector (talks to exchange) Market-making backtests are unreliable (no order-queue simulation)
Paper mode on real live data, for Binance and MEXC Dangerous defaults (20× leverage); hard-coded fees; some docs ≠ code

What could inspire our bot:

  • 🔁🥇 A connector interface where each exchange implements the same methods: place order, cancel, read trading rules, read balances, get order status, fees… The "read trading rules" method is where our symbol specs are read at runtime, e.g. MT5 volume_step/trade_contract_size, or Binance/MEXC filters.
  • 🔁🥇 A paper connector = real live prices + locally simulated fills. This is the answer for MEXC and PAXG, which have no testnet support in these projects.
  • 🔁 Strategies emit "actions"; executors own the order lifecycle. This keeps venue differences out of the brain. For example, MT5 attaches the stop-loss to the position, while spot exchanges need a separate stop order.
  • 🔁🥇 The triple barrier (stop, target, time limit). The time limit also caps swap costs on MT5.
  • 🔁 An inventory band (min / target / max) reused as a maximum exposure per symbol or currency.
  • 🪙 Market making itself: crypto only. On MT5 CFDs you pay the broker's spread instead of earning it. 🥇 On PAXG it would be an experiment at most: its thin order book and the weekend gap vs real gold make it an adverse-selection trap.

3.3 grid_trading_bot: a small, readable grid bot (with a dangerous trap)
Repo jordantete/grid_trading_bot
Popularity / activity ≈150 ★; active (v0.2.0 beta), with tests and CI
Licence MIT
Type Single-strategy grid bot: backtest, paper and live modes; spot only
Market label 🪙 Crypto (any ccxt exchange)

How the grid is built. You choose a price range (bottom → top) and a number of levels:

  • Arithmetic grid: levels spaced by the same amount of money (e.g. every $10).
  • Geometric grid: levels spaced by the same percentage (e.g. every 1%). This is better when prices move a lot, as metals and crypto do.
  • Optional ATR spacing: spacing = multiplier × ATR, and the grid is rebuilt when volatility changes too much. This uses live volatility, in line with our rule.

How it trades.

  1. It waits until the price is inside the range.
  2. It checks the grid is feasible against the exchange's minimums.
  3. It buys at market until 50% of the money is in coins. This is already a bet that the price will go up.
  4. It places limit buys below and limit sells above. Each filled buy creates a sell one level higher, and vice versa.

How it manages risk.

  • An absolute take-profit and stop-loss price, and an ATR trailing stop that only moves up. When any of these triggers, it cancels everything and sells at market.
  • Execution safety:
    • up to 3 retries
    • a circuit breaker (opens after 5 failures, retries after 60 s)
    • a health check every 60 s: if the price feed is older than 120 s it alerts; if the connection dies it cancels everything and stops
  • State: saved in SQLite (a small database in one file), with reconciliation against the exchange every 5 minutes.
🛑Caution

The trap: "paper trading" that is actually live. In this bot, paper mode means "use the exchange's test environment". For Binance that's the real testnet. But for exchanges without a sandbox, including MEXC, the code logs "No sandbox mode available… Running in live mode." and continues trading with your real API keys and real money.

Lesson for us: our connectors must fail closed. If we ask for demo, testnet or paper, and that mode doesn't exist, the bot must refuse to start, never silently switch to live.

Other weaknesses. Its backtests are optimistic:

  • a limit order fills if its price is anywhere inside the candle
  • stops are checked only at the candle close
  • zero slippage by default
  • no exchange minimums in backtests, so a backtest can accept grids that live trading would reject

Fees must be typed in by hand.

What could inspire our bot:

  • 🔁🥇 Grid maths (arithmetic vs geometric) as a test subject, preferably on PAXG rather than leveraged gold.
  • 🔁🥇 A feasibility check against the platform's minimums, applied in backtests too. On MT5 the 0.01-lot minimum on gold or silver can make a small-account plan impossible.
  • 🔁🥇 ATR-scaled spacing and an ATR ratchet trailing stop: volatility-normalised settings carry across forex, metals and crypto.
  • 🔁 Circuit breaker + "stale price feed → cancel and stop". This is especially important if the MT5 connection runs through a bridge (Part 8).
  • 🔁 SQLite state with a config fingerprint + regular reconciliation: the base for a journal and safe restarts.
  • 🚫 Never fall back from paper to live.

3.4 binance-trading-bot (chrisleekr): trailing buys and serious testing discipline
Repo chrisleekr/binance-trading-bot
Popularity / activity ≈5,600 ★; completely rewritten in Aug 2026 (v1, TypeScript). The famous old version is kept as v0-final
Licence Apache-2.0 (v1); MIT (v0)
Type Self-hosted bot for Binance spot only, long only. README: "not recommended for real funds"
Market label 🪙 Crypto (Binance)

How the "trailing trade" strategy works.

  • Trailing buy: instead of buying immediately, it places a stop-limit buy a little above the price and keeps moving it down while the price keeps falling. It buys only when the price turns back up.
  • Buy grid (averaging down): extra buys at lower levels relative to the average entry (e.g. another 30 USDT at −3%).
  • Sell: once the price rises above the average cost × e.g. 1.05, it trails a sell below the highest price since buying (e.g. ×0.98, i.e. sell after a 2% pullback). A hard stop-loss (e.g. ×0.97) always wins if both trigger.
  • Extra exits: ATR trailing, breakeven stop, time stop (exit after N candles).
  • Entry filters: RSI ceiling, SMA/EMA trend bias, and a daily trend filter (EMA 200: in a bear market, block new entries or exit to cash). It also recomputes TradingView's "technical rating" locally from 26 indicators.
  • Old v0 feature, "ATH restriction": don't buy above 90% of the 30-day high.

How it manages risk: the most complete of the four.

  • Exchange-side protective stop: a real stop order rests on Binance, so it works "even if the bot is offline".
  • Risk-based sizing: with a stop-loss set, the % you choose is risk per trade, capped at half the account per buy.
  • Exposure caps per symbol, per position and per account.
  • Entry breakers: daily loss limit, loss streak, drawdown pause (off by default).
  • Kill switch per coin, profile or account. It only blocks new orders; it doesn't sell or cancel.

How it tests: a model for us.

  • The backtester uses the same executor contract as live trading, with a realistic fill model:
    • a signal on candle N fills on candle N+1
    • limit orders fill only if the price trades through them
    • spread and slippage are charged
    • it can take at most 5% of a candle's volume
    • exchange filters are enforced
  • It also has a "live gate", a checklist before trusting a strategy:
    • profit factor ≥ 1.1
    • ≥ 100 trades
    • return ≥ buy-and-hold
    • the most recent 30% of data held out as out-of-sample
    • a backtest no older than 14 days that matches the current settings' fingerprint
  • An edge-decay monitor compares live results with the backtest every 15 minutes and warns when performance drops (below 0.85×, alarm below 0.6×).

Hard-coding check.

  • ✅ Exchange filters are fetched separately for testnet and production, because "testnet publishes coarser tickSize / lot filters than production". This is a great confirmation of our rule.
  • ❌ Fees are typed by the user and default to 0, so backtests look too good unless you set them.
  • The old v0 had insecure defaults (password 123456, UI exposed to the internet).

What could inspire our bot:

  • 🔁🥇 A pure decision function: market snapshot + state in, decisions out, with no network calls inside. The clock is injected, and it's tested with replayed "golden" examples. The same brain then works for backtest, paper and live.
  • 🔁🥇 Re-read symbol specs per environment on a schedule (testnet ≠ production; MT5 demo ≠ live; broker A ≠ broker B).
  • 🔁🥇 The fill model (next-candle fills, trade-through, spread, volume cap, filters), plus for MT5: real bid/ask, commission, swap, weekend gaps.
  • 🔁🥇 The live gate + edge-decay monitor as our checklist for moving a strategy from backtest → demo/testnet.
  • 🔁🥇 An exchange-side stop always: on MT5, send the stop-loss with the order; on Binance/MEXC spot, a separate stop order.
  • 🔁 Structured "why no trade" reasons (blockers) in the journal.
  • 🪙🥇 Averaging-down grids: crypto spot at 1× (or PAXG) only. On leveraged CFDs they behave like a martingale and pay swap.

An Expert Advisor (EA) is a bot that lives inside MetaTrader 5, written in MQL5, MetaTrader's own programming language, which looks like C++. EAs can use MT5's built-in Strategy Tester, the backtesting tool inside MT5, which can replay real historical ticks.

🧒Like I'm 10

An EA is like a robot that can only live in one house (MT5). It knows every room perfectly and can use all the house's tools. But it can't go next door to Binance or MEXC. Our bot must visit three houses, so we'll learn from these robots but build ours differently (in Python, with connectors).

How three of the strategies work (read from the code):

EA Indicators Buy rule (sell is the mirror) Stop-loss and target
BBRSI 🥇 (gold, M5) Bollinger Bands (500 candles, 2 std) + RSI(7) Two candles ago: RSI < 30 and price below the lower band. Last candle: RSI back above 30 and price back inside the band, but still below the middle. "Price dipped too far, then came back in" Stop a bit below the lower band; target = 1× the stop distance

How it manages risk: good parts.

  • Several sizing modes, including % risk: lots = money at risk ÷ (stop distance × value per tick). It reads the tick value from MT5 (it asks MT5 "how much profit would 1 tick make?"), which is the right idea. One simplification: it assumes the tick size equals the point.
  • Robust order sending: it checks the order first, detects which "filling mode" the broker accepts, and retries 5 times on temporary errors.
  • Trailing stop: it moves to breakeven at +0.5 R, then trails half a risk-distance behind the price.
  • Filters: margin level at least 300%, and an optional news filter (pause ±60 min around important news) and spread limit (both off by default).

How it manages risk: the dangerous part. By default the EAs run a martingale grid:

  • Each time the price moves one more stop-distance against the trade, the EA opens another trade in the same direction, 1.1× to 1.5× bigger than the last.
  • It does this up to 20 times (50 for one EA).
  • With the grid on, no stop-loss is sent to the broker at all.

We calculated that at the 20th level, the position is about 57× the first one (with ×1.1) or about 6,650× (with ×1.5).

The published results show the typical grid signature.

  • BBRSI on gold (Feb 2021 → Sep 2023): profit factor 2.31 and a smooth balance curve (the balance only changes when trades close), but a maximum equity drawdown of 35.7% (relative 70.2%).
  • 3MAF: equity drawdown 47.5%, and the margin level once fell to 36%, dangerously close to a stop-out (Guide Part 9).
  • The author honestly writes that each pure strategy "was not profitable over the long term" and only became profitable with the grid.
  • The tests used generated ticks and the same period the parameters were tuned on, so they are in-sample (see 0.3).

4.3 EarnForex PositionSizer: the position-size calculator 🔁🥇
Repo EarnForex/PositionSizer
Popularity / activity ≈590 ★; updated September 2026 (version 3.16)
Licence Apache-2.0 (permissive)
Type A tool (panel on the MT5 chart), not a strategy. It can also place the trade
Market label 🔁 Both for the formula · 🥇 an excellent lesson for metals · 💱 MT-only code
🧒Like I'm 10

Before jumping off a diving board you check how deep the water is. PositionSizer checks the depth for you: "you said you'll risk $10 and put your stop here, so your trade can be this big and no bigger."

What it calculates (from its core function):

Money at risk  = account size × risk %            (or a fixed amount)

                              Money at risk
Position size = ──────────────────────────────────────────────────
                (stop distance ÷ tick size) × tick value  +  2 × commission per lot

Then:

  1. It rounds the size down to the allowed lot step, then checks the broker's minimum and maximum.
  2. It shows the actual risk after rounding, because rounding changes the real risk slightly.
  3. If you want, it widens the stop by the current spread.
  4. It can place the stop and target at a multiple of ATR (Guide Part 11).

Why this is a key lesson for metals 🥇. For forex symbols, the tool uses MT5's ready-made tick value. For "CFD-mode" symbols, which is how gold and silver are set up at many brokers, it calculates the tick value itself:

tick size × contract size × exchange rate to the account currency

Every one of those numbers comes from the platform. This is exactly our "never hard-code" rule in action.

Example with made-up but realistic numbers: XAUUSD, $10,000 account, 1% risk ($100), stop $5 away, contract 100 oz → $100 ÷ ($5 × 100) = 0.20 lots. For silver, the contract is often 5,000 oz, so the same formula gives a much smaller size. The formula stays the same; only the platform's numbers change.

How it manages risk. Before sending a trade it checks a list of "fuses" and refuses (or shrinks) the trade if any is blown:

  • max spread, max slippage
  • min/max stop distance
  • max risk % per trade
  • max total risk across all open trades, max risk per symbol
  • max number of trades, max margin used

It also adds up the portfolio risk (the total risk of all open trades). A position without a stop-loss counts as infinite risk.

For crypto the same idea becomes: quantity = money at risk ÷ (stop distance × contract size + fees), where the contract size is 1 coin on spot. The result is then rounded down to the exchange's step size and checked against its minimum order value.

  • 🔁🥇 Our sizing function: one pure function that takes the symbol spec read from the platform + risk money + stop distance + costs, and works for EURUSD, XAUUSD, XAGUSD, BTCUSDT and PAXGUSDT alike.
  • 🔁 Round down, then report the real risk after rounding.

4.5 GOLD_ORB: an opening-range breakout on gold 🥇
Repo yulz008/GOLD_ORB
Popularity / activity ≈300 ★; last updated July 2023 (unmaintained)
Licence None → legally, the code may not be reused (see 0.1)
Type Single-strategy EA for XAUUSD on 1-hour candles, written as a beginner example
Market label 🥇 Metals (depends on gold's daily open on MT5)
🧒Like I'm 10

When the school gates open in the morning, kids run around wildly for a bit, then settle into a "zone" of the playground. The opening range is that first zone. A breakout is when someone suddenly runs out of the zone: the idea is to follow them.

How the strategy works.

  1. Opening range. The day starts at 01:00 broker server time. The first 1-hour candle of the day defines the range (its high and low).
  2. Stretching the range. New candles that make a new high or low stretch the range. It becomes final once 3 candles pass without a new extreme.
  3. Entry. When a green candle closes above the final range, buy at the next candle's open. When a red candle closes below it, sell. At most 1 buy and 1 sell per day.
  4. Exit. Stop-loss 400 points, take-profit 1,200 points (1:3), plus a trailing stop.

How it manages risk.

  • 1% risk per trade (capped at 10%).
  • A drawdown stop that halts real trading, while a "virtual shadow account" keeps trading on paper to decide when to resume.
  • An optional loss-streak stop.

Real problems found in the code (great lessons for us):

  • Hard-coded "points" (breaks our rule 🥇). 400 points is $4 of gold price on a broker that quotes gold with 2 decimals, but only $0.40 on a broker with 3 decimals, 10× smaller. The same EA behaves completely differently at different brokers. This is why we read digits, point and tick size from the platform and scale stops with ATR.
  • A bug stops all trading. Missing braces {} around a few lines mean that with the code's default settings (10% drawdown limit) no real order is ever sent. The shipped settings file happens to avoid it.
  • It touches other positions. The trailing stop loops over every position in the account (no magic number), so it would move the stops of your other trades too.
  • The server time is hard-coded. The day start at "01:00 server time" depends on the broker's time zone.

Claimed results. The README shows a backtest on gold from Feb 2019 to Jan 2021 with ideal execution, long trades only and 3% risk, and the readme says it's "profitable on bull market". That period was a strong gold uptrend, so long-only results there prove little: they're cherry-picked.

What could inspire our bot:

  • 🥇 Opening-range breakout on gold as a candidate idea to test, with the day start taken from the symbol's sessions read from MT5, not a hard-coded hour.
  • 🔁 Confirm a breakout with a candle close and cap trades per direction per day.
  • 🔁 The virtual shadow account: after a halt, keep paper-trading and only resume when the paper results recover.
  • 🔁🥇 ATR-scaled stops instead of fixed points.
  • 🪙 In crypto there is no daily open. We'd have to choose one (e.g. 00:00 UTC), which weakens the idea.

4.6 MT5-SMC-trading-bot: "Smart Money Concepts" in code 🔁🥇
Repo KVignesh122/MT5-SMC-trading-bot
Popularity / activity ≈90 ★; created 2025, updated 2026; one file of 558 lines
Licence Apache-2.0
Type Single EA; the README promotes paid products and a broker referral link
Market label 🔁 Both for the price-pattern logic · 🥇 advertised for XAUUSD

What "Smart Money Concepts" (SMC) means. A popular retail trading idea: that big institutions ("smart money") leave footprints on the chart. Its three main patterns:

  • Order Block (OB): the last opposite-colour candle before a strong move. The idea is that big orders sit there and price may come back to it.
  • Fair Value Gap (FVG): a gap between candle 1's high and candle 3's low (or the reverse) left by a very fast move. The idea is that price tends to come back to "fill" it.
  • Break of Structure (BOS): price breaks above the last swing high (or below the last swing low), suggesting the trend continues.

How the bot detects them (read from the code). All checks run once per new candle.

  • Displacement ("a strong candle"): the candle's range is at least ~1.2–1.8× ATR, its body is at least 60% of its range, and the next candle is also strong (2 of these 3 are needed).
  • Order block: the last opposite-colour candle before a displacement candle. It buys when the price returns into that zone and has pulled back at least 61.8% of the last swing (a Fibonacci level, a popular retracement ratio).
  • Break of structure: the price breaks the last swing high on a strong candle, but only when the market is trending. Trending means ADX(14) ≥ 18; ADX measures trend strength from 0 to 100. Or it means the Efficiency Ratio ≥ 0.30: how straight the price path was, where 1 = a straight line and 0 = pure zig-zag.
  • Filters: spread limit, trading hours 07:00–21:00 (GMT), one position per symbol.

Stops and sizing.

  • Stop-loss = 1.5 × ATR, take-profit = 2.5 × ATR (reward ≈ 1.67× risk).
  • But the size is not risk-based: 0.02 lots per $1,000 of balance, whatever the stop distance. The money at risk therefore changes with volatility.

Problems found in the code.

  • The FVG direction is reversed compared with the usual SMC definition: it buys where SMC traders would sell.
  • Old gaps are never removed, so every gap from the past stays "tradable" forever.
  • It uses the ATR of the still-forming candle, which changes until the candle closes.
  • The README claims "60%+ to 300%+ returns yearly on XAUUSD" but gives no backtest, period or settings: pure marketing.

What could inspire our bot:

  • 🔁 "Displacement" (strong-candle) and Efficiency Ratio as simple, measurable filters.
  • 🔁🥇 ATR-based stops and targets, which suit gold because it moves in dollars, not pips.
  • 🔁 If we ever test SMC ideas: define each pattern precisely, including when it becomes invalid, and unit-test it (automatic tests on small hand-made examples). This repo shows how easy it is to get the direction wrong.
  • 🚫 Ignore performance claims without published, reproducible tests.

What this does to metals 🥇: a perfect example of why we never hard-code.

XAUUSD at a broker with 3 decimals, 100 oz per lot 0.01 × 100 = 1 ❌ lots 10× too small

How a strategy is written. init() calculates indicators once. next() runs on every candle and can call buy() / sell() with a stop-loss and take-profit. Example from its README:

class SmaCross(Strategy):
    def init(self):
        self.ma1 = self.I(SMA, self.data.Close, 10)
        self.ma2 = self.I(SMA, self.data.Close, 20)
    def next(self):
        if crossover(self.ma1, self.ma2): self.buy()     # fast crosses above slow
        elif crossover(self.ma2, self.ma1): self.sell()  # fast crosses below slow

Honest fill rules.

  • Orders fill at the next candle's open.
  • When a candle touches both the stop-loss and the take-profit, the stop-loss is processed first (pessimistic).
  • A stop that the price gapped through fills at the open (realistic).

Statistics it reports (see 0.3): return, buy-and-hold return, Sharpe, Sortino, Calmar, max drawdown and its duration, number of trades, win rate, profit factor, expectancy, SQN (System Quality Number: a score of how consistent the trade results are) and Kelly. It can also draw heatmaps of optimisation results. A "broad plateau" of good settings is healthier than one lucky peak.

What it can't model.

  • No lots or contract sizes: it works in units. For gold, units = ounces, if you read the contract size from MT5.
  • Only a constant spread.
  • No swap or funding.
  • One symbol at a time (no portfolio).

Tiny, readable API; pessimistic fills; rich statistics No lots, swap, funding or currency conversion; constant spread only
Great for quickly checking signal logic Single asset; AGPL licence

6.2 FinRL: reinforcement learning for trading (≈16,500 ★)
Repo AI4Finance-Foundation/FinRL
Activity / licence Still updated, but described as the "educational and research" version (production moved elsewhere) · MIT
Market label 📈 stocks first · 🪙 partial (spot, long-only) · 💱 poor (no lots, leverage, swap or spread)

How it works. The market is turned into a game (called an environment):

  • State (what the AI sees): cash + prices + holdings + indicators (MACD, Bollinger, RSI, CCI, DX, SMA 30/60).
  • Action (what it does): how many shares to buy or sell.
  • Reward: the change in account value.

AI algorithms with names like PPO, A2C, SAC, TD3 and DDPG play the game many times on past data (the train period), then are tested on later data (the trade period).

A good idea: the "turbulence" switch. When the market becomes abnormally wild (measured statistically, or when the volatility index VIX ≥ 70), sell everything and stop buying.

Pitfalls we found in the tutorial code:

  • The test dates equal the trade dates, so there's no separate validation period.
  • Missing data is filled backwards (copying future values into the past), which is a form of look-ahead.
  • Only symbols that exist through the whole period are kept (survivorship bias, 0.3).
  • Trades fill at the same close the AI just saw.
  • No random seed, so runs can't be reproduced.

Its own FAQ admits buy-and-hold "may be very difficult to beat" and results on intraday data are "bad".

What could inspire our bot:

  • 🔁 A volatility "risk-off" switch: e.g. ATR far above its normal range → no new trades. 🥇 Very relevant for gold during US news.
  • 🔁 Separate train / validation / test periods, with the test used once.
  • 🔁 Always compare with a simple baseline (buy-and-hold for crypto; "do nothing" for forex).

6.3 FreqAI: machine learning inside freqtrade
Where A module of freqtrade (Part 2) · GPL-3.0
Market label 🪙 Crypto as a tool · 🔁 Both as ideas

How it works.

  1. You define features (inputs, columns starting with %) and a label (what to predict, columns starting with &, e.g. "average price over the next N candles vs now").
  2. A model (LightGBM, XGBoost, PyTorch…) is trained per coin on a rolling window (e.g. the last 30 days).
  3. The model is retrained regularly, also during backtests, which is proper walk-forward testing (0.3).
  4. Outlier gate ("Dissimilarity Index"): if today's inputs look very different from anything in the training data, the prediction is marked untrustworthy and no trade is taken.
  5. Example rule: long if the predicted change > +1% and the prediction is trustworthy; exit when the prediction turns negative. Stop −5%.

Warnings from its own docs: labels "intentionally look into the future" (so features must not), the example strategy is "not designed to be run in production", and continual learning has a "high probability of overfitting".

What could inspire our bot: 🔁 walk-forward testing, a "don't trade when inputs look unfamiliar" gate, and model/data expiry (don't act on stale information, which is critical for 24/7 crypto).

What it really is (from the code, not the marketing):

  • 🔁 Connector profiles: (demo / live) × (read-only / trading) × capability flags, with a runtime check that we are really on the demo or testnet.

  • 🔁 Never auto-retry orders; reconcile after restart.
  • 🔁🥇 One base backtest engine with per-market cost hooks (spread, swap, lots and ounces for MT5; fees, funding and coin units for crypto). Our costs, though, come from the platform's live data, not constants.
  • 🔁 A trade-journal behaviour checker (e.g. overtrading, chasing momentum, holding losers too long).
  • 🚫 An AI that places trades autonomously. 🚫 Orders without a broker-side stop.

7.2 Trading hours and breaks

  • Exness servers run on UTC+0. Several GitHub EAs assume GMT+2 (a common prop-firm convention), which would be wrong on Exness.
  • "Gold (XAUUSD) is usually closed during forex rollover": every Sunday–Thursday at 21:00 UTC in summer / 22:00 UTC in winter, usually lasting 1–2 hours, with wider spreads.
  • Metals follow US daylight-saving time (2026 changes: 8 March and 1 November).
  • HMR windows (lower leverage):
    • around the daily break: 30 min before to ~10 min after
    • around weekends: ~3 h before the close to 1 h after the reopen
    • around high-impact news: orders opened from 15 min before to 90 s after
  • Weekend maintenance: Saturday 04:00–08:00 UTC (summer) / Sunday 05:00–09:00 UTC (winter).
  • ⚠️ MT5's Python API cannot tell us the trading schedule (MQL5 has SymbolInfoSessionTrade; Python doesn't). The bot must detect "closed" from stale prices, trade_mode and error 10018, or get the sessions from a small MQL5 helper script (Part 8.6).

A promotion checklist before a strategy moves up a step (adapted from chrisleekr's "live gate"):

  • At least 100 trades in the backtest, across different market conditions.
  • Profit factor ≥ 1.1 after all costs (spread, commission, swap/funding, slippage).
  • Better than the simple baseline (buy-and-hold for crypto/PAXG; "do nothing" for forex and gold CFDs).
  • The most recent ~30% of data held out and passed (out-of-sample).
  • Walk-forward and Monte Carlo results acceptable; maximum drawdown we can live with.
  • Backtest settings fingerprint matches the settings being promoted.
  • Paper results match the backtest's behaviour (similar trade frequency, win rate and costs).

13.2 Mistakes we will not repeat

🚫 Anti-pattern Where we saw it Why it's dangerous
Martingale / multiplying grids, averaging down with leverage geraked, NFI, grid bots on CFDs Smooth results until one trend destroys the account
No broker-side stop-loss geraked (grid mode), Vibe-Trading MT5 orders A crash or disconnect leaves trades unprotected
Hard-coded symbol facts (points, pips, lot maths, server hours, filling mode) GOLD_ORB, jimtin, mqpy, EA31337 Wrong sizes on another symbol or broker (silver at 5× risk)
"Paper" silently becoming live grid_trading_bot on MEXC Real money lost while you think you're practising
Fees set to 0 or hard-coded chrisleekr (default 0), Hummingbot, grid bot Backtests look better than reality
Optimising on profit only, in-sample jimtin, geraked, EA31337 SETs Overfitting
Rules justified by single past events NFI Curve-fitting
Trusting marketing claims ("300% yearly") SMC bot, GOLD_ORB No evidence
Letting an LLM decide live trades TradingAgents-style systems Non-deterministic, untestable
Rounding up to the minimum lot EA_SCALPER, grid-master-pro Silently breaks the risk limit
Manual GMT offsets and news at fixed clock times EA_SCALPER (GMT+2), xaubot-ai (WIB times) Wrong on Exness (UTC+0) and wrong half the year (daylight saving)
Using code whose licence forbids it EA_SCALPER (no broker-connected use), GOLD_ORB and jimtin (no licence) Legal risk; another reason we re-implement ideas
Claims like "Sharpe 4.8" from in-sample tests xaubot-ai, GSR-Alpha Honest tests of similar ideas on gold (Aurum) found losses after costs
Platform if/elif spread through the code jimtin Adding a platform means rewriting everything
